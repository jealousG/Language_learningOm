# Проект «Читаем арабский» — состояние и соглашения

Личный сайт для изучения коранического арабского, Корана, хифза и фусхи.
**Стек:** статический HTML/CSS/JS, без сборщиков, серверов и зависимостей. Открывается как `index.html` (file://) — аудио с CDN работает. Запись голоса требует localhost/https.

## Запуск и проверка
- Сайт: открыть `index.html` в браузере (Chrome рекомендован).
- Самопроверка логики (SM-2, миграция, очередь, разделы «Слова»/«Грамматика», золотые чернила и уровни Основ, оживающая рукопись): открыть `selftest.html` (115 тестов, реальные данные localStorage бэкапятся и восстанавливаются). ВАЖНО: сводка пишется по стадиям, поэтому раннее чтение страницы даёт неполное число (только синхронные тесты) — автоматическая проверка должна ждать маркера `document.body.dataset.selftest === 'done'` и сверять число со числом строк `#results tbody tr`.

ВАЖНО (защита словаря от мусора): файлы `ДЗ - *.md` в словарь НЕ читаются (их таблицы — упражнения «слово | фраза | перевод», где перевод относится к фразе, а не к слову), строки с разметкой (`**жирный**`, `` `код` ``) и описания конструкций (ячейка с `+`) отбрасываются, а перевод из последней кириллической ячейки берётся только если таблица устроена как «слово | перевод» или «слово | чтение | перевод» (вторая ячейка не арабская). Иначе слову доставался перевод целой фразы или грамматическое пояснение. Пословный разбор: точная форма → без конечной огласовки → снятие артикля/приставок/суффиксов → дополнения (покрытие 100%). ЛЕММА (`WordBase`/`AddBaseTo`): в слово пишется поле `base` (словарная статья, по которой распознана форма) — по нему раздел «Слова» и тренажёр группируют формы одного слова (`أُخْتُكُمْ` → `أخت`). Снимаются ТОЛЬКО местоименные суффиксы (`هما هم هن كما كم كن ها نا ه ك ي`) и предлоги/артикль (`وال فال بال كال لل ال و ف ب ل ك`), падежные и числовые окончания НЕ снимаются (иначе «كتاب» слилось бы с «كتب»). ВАЖНО: (1) после снятия ПРИСТАВКИ основа должна быть не короче 3 букв (иначе «كان» = ك + ان слилось бы с частицей «إن»); (2) при присоединении суффикса ta marbuta переходит в `ت` (`صَدِيقَة` + `ي` = `صَدِيقَتِي`), поэтому проверяется и вариант основы с `ه`; (3) разбор должен быть ОДНОЗНАЧНЫМ — при двух кандидатах равной длины основа не угадывается (`وَفَّقَهُ` — это وفق+ه или و+فقه?); (4) ручное исключение задаётся полем `base` в `huna-extra-words.json`. Словарь глав курса (таблицы «Новые слова главы» из `00 MOC`) тоже читается в словарь — это и есть список основных слов курса. ВАЖНО: ta marbuta `ة` при нормализации превращается в `ه`, поэтому суффикс `ه` НЕ считается местоимением «его», если слово (до огласовок) оканчивается на `ة` (иначе «الجديدة» → «новый + его»); проверка — `ة` + огласовки в конце. Предлог+местоимение собираются в падежной форме (إِلَيْكَ → «к тебе», لا «к тебя»); إنّ+местоимение (إِنَّهَا → «поистине она») и частые притяжательные формы — в huna-extra-words.json. Отчёт о нераспознанных — huna-missing.txt. Требует BOM. |

## Модель данных
Story: `{id, type?: 'quran'|'hadith'|'story'|'adhkar'|'namaz', surahNo?, title, titleRu, level, intro, note? (пояснительный текст раздела, абзацы через \n → .story-intro), basmala?, sentences[]}`
Sentence: `{ayah?, ayahNumber?, ayahAudio?, ar, tr? (транслитерация — тексты намаза), ru, en? (Sahih International), when? (плашка «когда произносится» — для текстов намаза), words[]}`
Word: `{w, ru, tr?, root?, pos?, def?, audio?}` — аудио: cdn.islamic.network (аяты), audio.qurancdn.com/wbw/... (слова). Все URL проверены (CORS открыт).

## localStorage (ключи)
- `arabic-reader-mode-v1` — активный режим: `islam` (по умолчанию) | `arabic`. Режим задаёт пространство ключей: у Ислама — исходные ключи, у остальных режимов — те же ключи с суффиксом `__<режим>` (через `modeNs`). Раздельные по режимам: SRS слов, статистика тренажёра, журнал активности (теплокарта).
- `arabic-reader-ink-v1` — золотые чернила: {by: {раздел: число}, legacyBy: {основа: число}, legacy: 0, bootstrapped} — ГЛОБАЛЬНЫЙ ключ (общий для режимов, без modeNs); чернила копятся по разделам, но уровень «пути писца» — ОДИН на Основу (режим) и считается по `modeInk(mode)` = сумма её разделов + `legacyBy[mode]`. `legacyBy` — «ранее накопленное» (бутстрап из журналов активности всех Основ при первом обращении, разнесено по Основам по следу в этих журналах с сохранением общей суммы).
- `arabic-reader-progress-v1` — статусы слов читалки: "storyId:sIdx:wIdx" → seen|known (НЕ удалять)
- `arabic-reader-study-stats-v1` — статистика тренажёра: "текст слова" → {c, w, streak} (c/w — верные/ошибочные ответы, streak — верных подряд для «выучено»)
- `arabic-reader-srs-v1` — SRS слов: {cards, settings{newPerDay}, daily{date,newCount}, lastStoryId, migrated}
- `arabic-reader-hifz-v1` — SRS аятов: {ayat: "storyId:ayah" → карточка, last}
- `arabic-reader-activity-v1` — журнал дней: {days: {"ГГГГ-ММ-ДД": {reviews, correct, trainings, words}}} (words — проработанные слова за день, ось яркости теплокарты; история ~400 дней)
- `arabic-reader-routes-v1` — {visited, manual}
- `arabic-reader-story-status-v1` — статусы изучения сур: {storyId: learning|memorized} (переключение кликом по плашке на карточке, cycleStoryStatus)
- `arabic-reader-surah-filter-v1` — активный фильтр списка сур (all|learning|memorized)
- `arabic-reader-display-v1` — {harakat: full|partial|none}
- `arabic-reader-words-open-v1` — [id раскрытых глав] для раздела «Слова»; по умолчанию список пуст = все главы свёрнуты (при активном поиске/фильтре главы раскрываются принудительно)
- `arabic-reader-grammar-open-v1` — [id раскрытых глав] для раздела «Грамматика» (по умолчанию всё свёрнуто)
- `arabic-reader-reciter-v1` — выбранный чтец аятов (ar.alafasy | ar.husary | ar.mahermuaiqly); плеер читалки подменяет чтеца в URL через reciterUrl(). Выбор чтеца (`.reciter-control`) показывается ТОЛЬКО для аятов Корана: в озвучке материалов «Хуна Арабия» он скрывается (`initPlayer` переключает класс `hidden`). Подсветка звучащего аята — обводка + автопрокрутка к середине экрана (highlightAyah). Пословная подсветка («караоке») пробована и удалена по решению пользователя — без ручных таймкодов точной не сделать.

Карточка SRS: `{repetitions, intervalDays, ease(2.5, кламп 1.3–2.8), nextReviewAt, lastReviewedAt, lapses, totalAnswers, correctAnswers, lastResult, state: new|learning|review|relearning, introDate?, confidence?}`.
Лестница: «Хорошо» 10 мин → 1 д → 3 д → 7 д → рост ×ease (кап 365); «Не помню» → relearning +10 мин; «Легко» → сразу 7 дней. ВАЖНО: ease обновляется ДО расчёта интервала («Легко» в review: 7 × 2.65 × 1.3 → 24 д). Серия дней: ≥3 ответов или 1 тренировка в день.

Чернила: `INK.add(n, section)` — раздел обязателен для точной атрибуции (см. js/ink.js); уровень считается по числу чернил ОСНОВЫ (`INK.modeLevel(mode)`), а раздел влияет только на разбивку. Окно «Уровни» (`#levelsModal`, app.js `openLevelsModal/closeLevelsModal/renderLevelsModal`) открывается из чипа уровня на Главной и из «Мой прогресс»; в списке модалок для Tab-ловушки оно учтено. Порядок содержимого окна: лестница ступеней с отметкой «Вы здесь» (плюс бейдж второй Основы) → «Как копятся чернила» → разбивка чернил по разделам → «ранее накоплено».

## Ключевые правила (соблюдать!)
- SM-2 только через `SRS_CORE.applyGrade` — не дублировать.
- Экранирование только через `escHtml`/`esc`/`escapeHtml` (делегируют в util.js).
- Оценка слова — только через `SRS.gradeWord` (единая точка: расписание + статистика + активность).
  - Изучаемость слова — только через `isStudyableWord(w)` (words-core.js): имена собственные и цифры/ссылки на аяты в «Слова», тренажёр и SRS не попадают (фильтр применён в `chapterWordEntries`, `wordOwnerMap`, `uniqueWordItems`, `newWordsPool`, `SRS.buildCorpus`), но в `sentences[].words` остаются — иначе ломается склейка `words[].w` = `ar`.
  - Один аудиопоток: `stopAllAudio(keep)` (app.js) — единая точка. Любое новое воспроизведение глушит предыдущее: слово (`playWordAudio`), плеер читалки (`playPlayer`), Хифз (`HIFZ.playOnce/playSequence`), воспроизведение своей записи (`playRecording`); `switchTo` глушит всё. Параметр `keep` — стартующий сейчас источник (`'word'|'player'|'hifz'|'rec'`), его не глушим. `playRecording` хранит ссылку `recAudio` (иначе запись нечем остановить).
- Арабский текст Корана не менять; огласовки — только визуальная копия (visualWord, regex `[\u064B-\u0653\u0670\u06D6-\u06ED]`, НЕ трогать U+0654/0655 — хамза).
- ВАЖНО: в каждом предложении склейка `words[].w` должна равняться тексту `ar` — каждое слово арабского текста разобрано отдельно (проверяется смоук-скриптом: нормализация без огласовок, сравнение строк). `ﷺ` (U+FDFA) и числа — тоже отдельные «слова» с переводом (в импортёре `SpecialWord`, включая ссылки вида «(96:1-5)»; в ручном разборе `data-vault-words.js` добавляются вручную). Проверка на текущем дереве: 0 расхождений.
- data-juz30.js не редактировать вручную — только пересборка tools/build-juz30.ps1. Аналогично data-vault.js — только пересборка tools/import-obsidian.ps1.
- Глобальные модули — `const` (НЕ window.X): проверять `typeof SRS !== 'undefined'`.
- Режим («Ислам»/«Арабский язык») — единственный источник набора вкладок и пространства ключей: ключи хранилища брать только через `modeNs(...)`, тексты режима — через `modeStories()`, источники тренажёра — через `modeSources()`. Раздел вне текущего режима `switchTo` перенаправляет на «Главную».

## Известные ограничения / roadmap
- Нет автопроверки произношения/таджвида (намеренно); запись голоса — только self-listen, требует localhost/https.
- Корни/вхождения — только по материалам сайта. Разметка таджвида удалена из UI по решению пользователя (кнопка «Таджвид» и «Показать оригинал» убраны; tajwid-markup.js отключён от index.html).
- Восстановление позиции: sessionStorage `arabic-reader-ui-state-v1` ({section, storyId, y}) — после F5 возвращается раздел + открытый текст + прокрутка (см. saveUiState/restore в app.js).
- Нет аудио для хадисов/историй/текстов намаза (нет надёжного открытого источника; TTS пробовали и удалили по решению пользователя). Аяты Корана — только аудио Афаси с CDN. Формулы намаза снабжены транслитерацией (sentence.tr).
- Нет ручного ввода арабского (архитектура готова), нет лемматизации, нет синхронизации между устройствами.
- «Хуна Арабия»: пословный разбор строк — покрытие 100% (словарь из заметок-слов/корней/таблиц глав и диалогов + ручные дополнения `tools/huna-extra-words.json`; непокрытое помечается `miss` и выгружается в `tools/huna-missing.txt`). Аудио материалов «Хуна Арабия» — ПОСТРОЧНОЕ: файлы `audio/<папка тома>[/<подпапка>]/<id материала>-<номер>.mp3` (например `audio/Huna Arabia 2 том/huna2-g9-d1-3.mp3` — третья реплика диалога 1 главы 9, или `audio/Huna Arabia 2 том/Озвучка_Глава10/huna2-g10-d1-1.mp3`), импортёр сам проставляет `sentences[].audio`, если файл существует (поиск рекурсивный по папкам томов — папка тома содержит цифру в имени). Озвучены главы 9–16 Тома 2: 23 материала из 24, 117 реплик (не записан диалог 2 главы 11; текст 2 главы 16 — 6 реплик из 7). В читалке такое аудио играет общий плеер (как аяты), плюс у каждой озвученной реплики значок ▶ (клик — играть с этой реплики; у частично озвученного материала, где плеер не собирается, значок играет только эту реплику). Разделы книг компактные: глава = только название + материалы в строку (до 4 в ряд); слова главы и «Грамматика главы» убраны из книг; вся грамматика — в отдельном разделе «Грамматика» (56 заметок). Карточка материала — крупная (на всю ширину сетки): название («Диалог N»), тема и персонажи из таблиц глав + значок «Aa» (тренажёр по этому материалу). Домашние задания (ДЗ) не импортируются.
- Кандидаты на улучшение: караоке-подсветка слов по таймкодам, TTS для хадисов, экспорт/импорт прогресса.
